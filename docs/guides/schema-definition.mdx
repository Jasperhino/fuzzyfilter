# Schema Definition (V2 API)

This guide explains how to define schemas for FuzzyFilter V2, including native enum support and column types.

## Column Types

FuzzyFilter V2 supports built-in types and native TypeScript enums:

### String Columns

For free-text fields:

```typescript
{
  id: "title",
  labelKey: "columns.title", // i18n key (required)
  type: "string",
}
```

**Supported operators**: `eq`, `neq`, `contains`, `notcontains`, `startsWith`, `endsWith`, `isempty`, `isnotempty`

### Number Columns

For numeric fields:

```typescript
{
  id: "priority",
  labelKey: "columns.priority",
  type: "number",
}
```

**Supported operators**: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `isempty`, `isnotempty`

### Date Columns

For date/datetime fields:

```typescript
{
  id: "createdAt",
  labelKey: "columns.createdAt",
  type: "date",
}
```

**Supported operators**: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `isempty`, `isnotempty`

Date columns automatically support natural language expressions like "today", "last week", etc.

### Native Enum Columns (V2)

For fields with a known set of values - **no `type: "enum"` needed!**

```typescript
// Native TypeScript enum
enum Status {
  OPEN = "Open",
  CLOSED = "Closed",
  IN_PROGRESS = "In Progress",
}

// Column definition - just provide values!
{
  id: "status",
  labelKey: "columns.status",
  values: Object.values(Status), // Automatic enum handling!
  valuesI18nPrefix: "status", // Maps to "status.Open", "status.Closed", etc.
}
```

**Supported operators**: `eq`, `neq`, `in`, `notin` (equality operators work automatically!)

The `values` array triggers enum mode - the library automatically handles parsing, formatting, and comparison. Equality operators work automatically because they use simple `===` comparison.

### Boolean Columns

For true/false fields:

```typescript
{
  id: "isActive",
  labelKey: "columns.isActive",
  type: "boolean",
}
```

**Supported operators**: `eq`, `neq`, `isempty`, `isnotempty`

Boolean columns automatically suggest `true` and `false` as values.

## Column Options

All column types support these optional properties:

### Column Aliases

Provide alternative names for fuzzy matching:

```typescript
{
  id: "createdAt",
  labelKey: "columns.createdAt",
  type: "date",
  aliases: ["created", "creation date", "date created"],
}
```

This allows users to type "created" or "date created" and still match the column.

### Column Description

Add a description for tooltips or help text:

```typescript
{
  id: "priority",
  labelKey: "columns.priority",
  type: "number",
  description: "1 = highest priority, 5 = lowest",
  descriptionKey: "descriptions.priority", // i18n key for description
}
```

### Enum Value i18n Prefix

For enum columns, specify the i18n key prefix for value translations:

```typescript
enum Status {
  OPEN = "Open",
  CLOSED = "Closed",
}

{
  id: "status",
  labelKey: "columns.status",
  values: Object.values(Status),
  valuesI18nPrefix: "status", // Maps to "status.Open", "status.Closed"
  // If omitted, defaults to column id ("status")
}
```

## Complete Schema Example (V2)

```typescript
import { createFuzzyFilter, createDefaultEnglishProvider } from "fuzzyfilter";

// Native enums
enum Status {
  OPEN = "Open",
  CLOSED = "Closed",
  IN_PROGRESS = "In Progress",
  PENDING = "Pending",
  BLOCKED = "Blocked",
}

const filter = createFuzzyFilter({
  columns: [
    {
      id: "status",
      labelKey: "columns.status",
      values: Object.values(Status), // Native enum - automatic!
      valuesI18nPrefix: "status",
      aliases: ["state", "progress"],
    },
    {
      id: "priority",
      labelKey: "columns.priority",
      type: "number",
      description: "1-5 scale, 1 is highest",
      aliases: ["importance", "urgency"],
    },
    {
      id: "assignee",
      labelKey: "columns.assignee",
      type: "string",
      aliases: ["assigned to", "owner", "responsible"],
    },
    {
      id: "createdAt",
      labelKey: "columns.createdAt",
      type: "date",
      aliases: ["created", "creation date"],
    },
    {
      id: columnId("dueDate"),
      name: "Due Date",
      type: "date",
      aliases: ["deadline", "due"],
    },
    {
      id: columnId("isBlocked"),
      name: "Blocked",
      type: "boolean",
      aliases: ["stuck", "waiting"],
    },
    {
      id: columnId("tags"),
      name: "Tags",
      type: "enum",
      values: ["bug", "feature", "docs", "test", "refactor"],
      aliases: ["labels", "categories"],
    },
  ],
});
```

## Dynamic Values

For enum columns where values come from your data:

```typescript
// Extract unique values from data
const statuses = [...new Set(data.map(row => row.status))];

filter.setSchema({
  columns: [
    {
      id: columnId("status"),
      name: "Status",
      type: "enum",
      values: statuses,
    },
  ],
});
```

## Schema Updates

You can update the schema at any time:

```typescript
// Initial schema
filter.setSchema({ columns: [...] });

// Later, update with new columns or values
filter.setSchema({
  columns: [
    ...existingColumns,
    { id: columnId("newColumn"), name: "New Column", type: "string" },
  ],
});

// Re-index data after schema changes
filter.indexData(data);
```

## ColumnId Helper

The `columnId` function is a helper that returns the string as-is:

```typescript
import { columnId, type ColumnId } from "@jasperhino/fuzzyfilter";

const statusId: ColumnId = columnId("status");
const priorityId: ColumnId = columnId("priority");

// TypeScript ensures you use valid column IDs
filter.compileFilter(statusId, "eq", "Open");
```

## Best Practices

1. **Use descriptive names**: Column names appear in suggestions, so make them user-friendly
2. **Add aliases**: Include common synonyms users might type
3. **Limit enum values**: Very large enum lists can slow down suggestions
4. **Use accessors for computed values**: Don't duplicate data in your objects
5. **Update schema and re-index together**: Schema changes require re-indexing
